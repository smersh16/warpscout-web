# WarpScout Web для Ubuntu

Веб-версия WarpScout: то же Go-ядро, что и в Android-приложении (`mobileapi`), но вместо Kotlin-интерфейса —
HTTP-сервер со встроенным веб-интерфейсом (`cmd/warpscout-web`, `internal/webserver`). Сканирование выполняется
на сервере; аккаунт WARP и история хранятся в каталоге данных (`/var/lib/warpscout-web`, права 0600).

## Установка (Ubuntu 22.04+)

```bash
git clone <URL этого репозитория> warpscout-web && cd warpscout-web
sudo ./deploy/ubuntu/install.sh          # по умолчанию слушает только 127.0.0.1:8787
# внешний доступ: sudo LISTEN=0.0.0.0:8787 TOKEN=мой-токен ./deploy/ubuntu/install.sh
```

Скрипт ставит Go (если нужной версии нет), собирает бинарник в `/usr/local/bin/warpscout-web`, создаёт
пользователя `warpscout` и systemd-сервис `warpscout-web`. В конце печатается токен доступа
(также лежит в `/var/lib/warpscout-web/token`).

По умолчанию сервис доступен только с самого сервера. Самый простой безопасный способ открыть его со своего компьютера — SSH-туннель:
`ssh -L 8787:127.0.0.1:8787 user@сервер`, затем `http://127.0.0.1:8787/`. Для прямого доступа по адресу включите HTTPS (ниже) или запустите установку с `LISTEN=0.0.0.0:8787`.

## Безопасность

* Слушает `127.0.0.1` по умолчанию. Внешний адрес задаётся явно (`LISTEN`, `-listen`).
* Доступ по токену. После входа выдаётся случайный идентификатор сессии (cookie `HttpOnly`, `SameSite=Strict`),
  который хранится на сервере и действует 7 дней; «Выйти» отзывает его немедленно. Перезапуск сервиса сбрасывает сессии.
* Подбор токена ограничен: 5 неверных попыток с одного IP за 15 минут блокируют токен-авторизацию этого IP на 15 минут (HTTP 429).
  За reverse proxy включите `WARPSCOUT_TRUST_PROXY=1` (или `TRUST_PROXY=1` при установке), иначе все запросы будут выглядеть как
  приходящие с адреса прокси. Включайте только если прокси сам выставляет `X-Forwarded-For`.
* Экспорт аккаунта (там приватный ключ) требует повторного ввода токена и пишется в журнал.
* От CSRF защищают заголовок `X-WarpScout` и `SameSite=Strict`.
* По HTTP токен идёт открытым текстом. Для доступа из интернета включите HTTPS:
  * reverse proxy: `LISTEN=127.0.0.1:8787` + `deploy/ubuntu/Caddyfile.example` (или nginx с `proxy_buffering off`), либо
  * встроенный TLS: в `/etc/warpscout-web.env` добавьте `WARPSCOUT_TLS_CERT=/path/fullchain.pem` и
    `WARPSCOUT_TLS_KEY=/path/privkey.pem` (файлы должны читаться пользователем `warpscout`), затем `systemctl restart warpscout-web`.
* SOCKS-прокси слушает только `127.0.0.1` сервера. Снаружи — через SSH: `ssh -L 1080:127.0.0.1:1080 user@server`.
* Операции выполняются по одной за раз; вкладку можно закрыть — прогресс и результат сохраняются на сервере.

## Возможности веб-версии

* Пресеты считает сервер (`core.ScanSpec.Resolve`), браузер присылает пресет и форму экспертного режима. Правила те же, что в Android.
* Исключение стран и узлов, копирование лучшего адреса, CSV, текстовый отчёт, конфиги WireGuard/AmneziaWG/usque/Mihomo, флаги стран.
* Результаты «Поиск AWG junk/I1» и «Поиск MASQUE SNI» сохраняются на сервере; кнопка «Применить к сканированию» подставляет их в форму.
* **Проверка Telegram.** Флажок «Проверить Telegram» через каждый поднятый туннель отправляет настоящий MTProto-запрос (`req_pq_multi`)
  ко всем пяти дата-центрам Telegram. Просто открытого TCP-соединения мало: DPI завершает handshake и молча съедает данные, поэтому
  дата-центр засчитывается только после ответа. Адрес считается рабочим для Telegram, когда ответили **все пять** (аккаунт живёт на одном ДЦ
  и клиент не может выбрать другой). В таблице колонка Telegram показывает `✓ N мс` (ответ самого медленного ДЦ), `3/5` или `заблокирован`;
  такие адреса идут выше остальных независимо от пинга. «Только с Telegram» убирает остальные и ранжирует оставшиеся по времени ответа Telegram.
  Проверка добавляет до одного таймаута на адрес с заблокированным Telegram. Для поиска junk/SNI и SOCKS она не выполняется.
  Идея и код проверки — из [niklzz/warpscout-tg](https://github.com/niklzz/warpscout-tg) (MIT).
* История хранит и форму сканирования, поэтому «Открыть» восстанавливает все параметры.

## Управление

```bash
sudo systemctl status warpscout-web
sudo journalctl -u warpscout-web -f
sudo systemctl restart warpscout-web
```

Без установки (для проверки): `go run ./cmd/warpscout-web -listen 127.0.0.1:8787 -no-auth`.
Демо-режим интерфейса без сети и аккаунта: добавьте `-demo`.

## Docker

Проще всего: `docker compose up -d --build` в корне проекта (файл `docker-compose.yml`; токен задайте в `.env`: `WARPSCOUT_TOKEN=...`).
Стек в Portainer должен брать код из репозитория, где лежат `Dockerfile.web` и `docker-compose.yml` (ваш форк), либо используйте готовый образ, собранный на сервере.

Вручную:

```bash
docker build -f Dockerfile.web -t warpscout-web .
docker run -d --name warpscout -p 8787:8787 -v warpscout-data:/data -e WARPSCOUT_TOKEN=мой-токен warpscout-web
```
